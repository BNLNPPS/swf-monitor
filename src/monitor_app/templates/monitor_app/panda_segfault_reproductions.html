Segfault Reproduction Runs

Every attempt to run a crashed row again: the operator's request from a signature page, the canary job the canary agent submitted for it on the production queue or the reference queue BNL_NPPS_GPU, and what the payload did. One row per attempt, the queued and running ones first, then the ended ones newest first. Execution and result are kept apart: a finished PanDA job is not a payload that ran clean, and a failed one is not a crash; the result comes from the payload's own exit code in its report, or from the job digest when the job failed after the payload ran.

Definitions
  • Execution, where the attempt is:
    • Queued for submission: the request is recorded, no canary run answers it yet; the agent has it, or its dispatch failed before a run was recorded.
    • Submitting: the agent accepted it, no PanDA task yet.
    • Queued: the task is submitted and the job has not started (the PanDA state is shown).
    • Running, Finishing: the job runs, or is past running (holding, transferring).
    • Finished, Failed, Cancelled: the job ended; the PanDA verdict on the job, not on the payload.
    • Submission failed: no task could be made; the reason is on the row.
  • Result, what the payload did:
    • Pending: the job has not ended.
    • Awaiting report: the job ended; the next collection reads its report.
    • Crash reproduced: the payload died on a signal (exit 134, 135, 136 or 139).
    • Completed without crash: the payload ran to exit 0.
    • Inconclusive: the run says nothing about the crash; the reason is on the row (another payload exit, a missing report, a job failure before the payload, a failed submission).
  • Waited: from the job's creation to its start. Ran: from start to end; for a job still running, the time so far, marked.
  • Observed: when PanDA was last read for the attempt by the probe collection; a page reload does not read PanDA.
