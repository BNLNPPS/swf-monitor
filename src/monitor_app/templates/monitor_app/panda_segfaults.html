Segfault Catalog

Payload crashes in ePIC production jobs, one row per crash signature: a job whose payload died on a signal (exit code 128 plus the signal: 139 SIGSEGV, 134 SIGABRT, 135 SIGBUS, 136 SIGFPE), found from the PanDA record and grouped by exit code and PanDA task at record level; signatures sharing a crashing frame merge into one trace-level entry once dug. Rebuilt nightly by the catalog sync; the crashed jobs behind each row carry their manifest row where the attempt's manifest is on record.

Definitions
  • Class, read from the record alone:
    • Storm: a fixed time to death across many nodes, one deterministic cause (crash rate at or above 20% and the middle half of the deaths within 20% of the median).
    • Config dead: the configuration cannot run at all (95% or more of the task's jobs crash).
    • Sparse: a few crashes at varying times, about one per host; where event-dependent crashes live (under 5% of the task's jobs).
    • Abort: exit 134, the program aborted itself (an exception or assertion), whatever the rate.
    • Mixed: none of the above; a class to look at, not a verdict.
  • Status, where the signature stands from first sighting to a verdict:
    • new: on the record, nothing read yet.
    • digging: a representative job's payload log is being fetched.
    • traced: the crashing frame is on record.
    • reproducing: the crashed row is running again as canary jobs on the production queue and the reference queue.
    • reproduced: a rerun crashed (on both queues, or on the production queue alone: site dependent).
    • not reproduced: neither rerun crashed.
    • diagnosed: the LLM study has classified the crash and named the operator action.
    • handed off: the study handed the crash to the software experts with the reproduction package.
    • fixed: a fix is named (the fixing image or commit); the residual rerun under it closes the signature.
    • accepted: production accepted the stated loss.
  • Manifest row: the unit of work of a production job, one line of the task's manifest: the EVGEN input file, its extension, the number of events, and the chunk index; the payload skips chunk × events into the file, simulates and reconstructs those events with the seed chunk + 1, and writes one output named by the row. A crashed job's row is what a reproduction runs again.
  • Rows lost: crashed manifest rows with no delivered output in any attempt of the configuration (and the events they carried).
  • TTD, time to death: minutes from job start to the crash, the 10th and 50th percentile over the signature's crashed jobs.
  • Rate: the signature's crashes over the task's finished plus failed jobs.
  • Stage: where the payload died, simu (npsim) or reco (eicrecon), where the jobs' payload digest carries it.
