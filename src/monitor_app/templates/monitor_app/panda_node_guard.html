Node guard

The guard finds a node that takes production jobs and kills them fast: every few minutes it reads the window's finished and failed jobs per queue and host, and a host whose jobs mostly fail, fail fast, and belong to tasks that finish on the queue's other nodes is a black hole. Mode {{ mode }}{% if mode == 'shadow' %} (judges, records and announces; excludes nothing){% endif %}; guard {% if enabled %}on{% else %}off{% endif %}. {% if never_run %}No cycle has run yet.{% else %}Last cycle {{ cycle_at }} ({{ state.duration_s }} s), every five minutes, over the last {{ settings.window_h }} h.{% endif %} The switches and thresholds are the node_guard settings on the System page; the verdicts are on the action stream; the plan is NODE_GUARD.md.

Definitions
  • Node: the batch host a job ran on, as the job record names it, within its queue. A node's slots are one node.
  • Site: where the node actually is. For a pool queue (the OSG queues) the site the pilot reported from the glidein, else the site the node's domain names; the queue itself elsewhere. Blank for a bare host name the record cannot place.
  • First, Last: the end times of the node's first and last job in the window, Eastern.
  • Evidence: the triangle on each row opens the node's evidence: the tasks it failed with the nodes they finished on, how long its failures ran, their error codes, and its most recent failed jobs.
  • Judged: a node with at least {{ settings.min_jobs }} finished or failed production jobs in the window. Nodes with fewer are counted, not judged.
  • State of a cycle's reading: would exclude (shadow mode) or excluded (live): the node read as a black hole this cycle; clear: it did not, for the reason shown.
  • Record: the node's standing in the node map. black hole: tripped, and held for {{ settings.expiry_h }} h from the trip whatever later cycles read; half open: the hold expired, one job may land there, a clean landing clears the node and a fast failure reopens it for twice as long; pinned: a person's decision, the guard never changes it; a cleared node leaves the record.
  • Black hole: at least {{ settings.failed_fraction|floatformat:"-2" }} of the node's jobs failed, at least {{ settings.fast_fraction|floatformat:"-2" }} of the failures were fast, and at least one task the node failed finished on another node of the queue in the last {{ settings.attribution_h }} h.
  • Fast: a failure shorter than {{ settings.fast_ratio|floatformat:"-2" }} of the queue's median finished walltime (the queue table shows the minutes). A failure with no recorded duration counts against tripping.
  • Fixed-time kill: a node that finished nothing in the window and whose failures all die at the same time (the 90th percentile of their durations within {{ settings.fixed_time_ratio|floatformat:"-2" }} of the 10th), from {{ settings.fixed_min_jobs }} failures up, whatever the speed, when at least one of its tasks finished on another node of the queue; a memory ceiling or a slot that kills at its limit. Read after the standard rule.
  • Reason for a clear node:
    • failed share under the threshold: the node finishes enough of its jobs.
    • failures not fast: the node's jobs fail, but late; not a black hole.
    • its tasks finish nowhere on the queue: the queue's other nodes finish other work but none of these tasks; the task's condition.
    • no other node on the queue: nothing finished on any other node of the queue in the attribution window, so node and queue are one thing here; the queue's failure detectors are the instrument.
    • the queue's event: more than {{ settings.storm_nodes }} nodes of the queue tripped at once; a storm, the queue's condition, not the nodes'.
    • no calibration for the queue: the queue finished no production job in 14 days, so fast cannot be defined.
  • Not a node: a submit host a job dies on before it lands ({{ settings.not_nodes|join:", " }}); never judged, its outcomes shown beside the queue.
  • A trip is always recorded on the action stream; a clear after a trip, and a standing trip hourly.
